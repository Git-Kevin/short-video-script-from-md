# ShortVideo

This repository contains Codex skills for turning Markdown into short-form content assets plus the repo-level safety checks used to keep those skills clean and portable.

Current skills:

- `shortvideo-from-md`: turn Markdown into short-video production packages
- `xhs-titles-from-md`: turn Markdown into Xiaohongshu title matrices

The skills can turn Markdown content into assets such as:

- spoken scripts
- clean narration
- shot-by-shot storyboards
- subtitle copy
- platform variants for Douyin, Xiaohongshu, Bilibili, Reels, and similar workflows

## Quick Start

After cloning or syncing this repo onto a new machine, run:

```powershell
python -m pip install pre-commit
python scripts/install_local_hooks.py
pre-commit run --all-files
```

Windows-only convenience command:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-local-hooks.ps1
```

What this does:

1. installs the Python dependency used by local Git hooks
2. generates a repo-local `pre-commit` hook in `.githooks/pre-commit`
3. sets `git config core.hooksPath .githooks`
4. uses `.cache/pre-commit` as the local hook cache
5. enables Gitleaks scanning before each commit

The first `pre-commit` run needs network access because it downloads the Gitleaks hook environment from GitHub.

## Local Hook Setup

This repo does not rely on the default shell-based hook generated by `pre-commit install`.

Instead it uses a repo-local Python hook because that is more reliable in this Windows environment and avoids the `/bin/sh` issues we hit earlier.

Install or refresh the hook with:

```powershell
python scripts/install_local_hooks.py
```

Re-run that command when:

- Python moves to a different path
- you switch Python environments
- you clone the repo on a different machine

Useful checks:

```powershell
git config --get core.hooksPath
pre-commit run --all-files
```

Expected result:

- `git config --get core.hooksPath` prints `.githooks`
- `pre-commit run --all-files` runs without shell errors

## Secret Scanning

This repo checks for hardcoded secrets in two places:

1. locally through `pre-commit`
2. in GitHub Actions through `.github/workflows/gitleaks.yml`

Relevant files:

- `.pre-commit-config.yaml`
- `.gitleaks.toml`
- `.github/workflows/gitleaks.yml`

Manual scan examples:

```powershell
pre-commit run gitleaks --all-files
```

```powershell
$files = git diff --cached --name-only
pre-commit run gitleaks --files $files
```

## Skill Usage

Each skill source lives under `skills/`.

To make a skill available in your Codex skills directory, copy that skill folder into your local skills home using the same folder name.

Typical destination:

- Windows: `%USERPROFILE%\.codex\skills\<skill-name>`
- macOS / Linux: `$HOME/.codex/skills/<skill-name>`

Once a skill is available to Codex, you can invoke it with prompts like:

```text
Use $shortvideo-from-md to read README.md and turn it into a short-video script package.
```

```text
Use $xhs-titles-from-md to read README.md and generate multiple Xiaohongshu title types.
```

Core behavior for `shortvideo-from-md`:

- read the full Markdown source before writing
- compress the source into one strong video angle
- default to colloquial Mandarin short-video delivery unless the user asks otherwise
- output the smallest package that satisfies the request

Useful supporting files:

- [skills/shortvideo-from-md/references/style-presets.md](skills/shortvideo-from-md/references/style-presets.md)

- [skills/shortvideo-from-md/agents/openai.yaml](skills/shortvideo-from-md/agents/openai.yaml)

Core behavior for `xhs-titles-from-md`:

- read the full Markdown source before writing titles
- extract the strongest click reason from the body content
- return a balanced mix of 6 Xiaohongshu-native viral title types by default:
  `emotional-resonance`, `pain-point-tutorial`, `numbered-list`, `curiosity-reversal`, `audience-targeted`, `review-comparison`
- keep the titles truthful to the source instead of inventing hype
- prefer the practical formula `target audience + pain-point scene + emotion word or number + solution` when it fits the source

## Troubleshooting

### `pre_commit` cannot be imported

Install it into the Python you are using for the repo:

```powershell
python -m pip install pre-commit
```

### `git hook run pre-commit` fails after switching Python

Reinstall the repo-local hook:

```powershell
python scripts/install_local_hooks.py
```

### `pre-commit run --all-files` says `no files to check`

That usually means there are no tracked files yet. Stage or commit files first, or pass file paths directly:

```powershell
pre-commit run gitleaks --files README.md .pre-commit-config.yaml
```

### Git is installed but not on `PATH`

The PowerShell installer checks a few common Windows Git paths. If you are using another install location, add Git to `PATH` first.

## Daily Workflow

Typical loop after the first setup:

```powershell
git pull
python scripts/install_local_hooks.py
pre-commit run --all-files
git add .
git commit -m "your message"
```

On the same machine, you usually only need to reinstall hooks again when Python changes.
